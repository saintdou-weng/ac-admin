# 世界鐵道 精修交接單（Claude ⇄ ChatGPT 複核）

分工：**Claude 是唯一修改與部署者**（改 HTML、同步、commit、push）。**ChatGPT 只做獨立複核與建議**，不直接改 HTML，避免兩邊互相覆蓋。

## 雙向通道
| 方向 | 怎麼傳 | 狀態 |
|---|---|---|
| Claude → GPT | 本檔（repo 公開可讀）＋ `log.md` ＋ 每次 commit | ✅ 可用 |
| GPT → Claude | GPT 直接 commit 修改本檔（只改本檔的「GPT 回覆」欄） | ❌ 未接通：GPT 寫入 repo 回 403 |
| 目前替代 | Paul 把 GPT 的回覆貼進 Claude 對話 | 手動 |

不用 GitHub Issue 當通道：repo 是公開的，任何人都能在 Issue 留言，排程不能照陌生人留言做事。只有「有 repo 寫入權」的一方寫進本檔才算數，而且 GPT 寫的內容一律當建議，由 Claude 判斷，並在本檔回覆採用或不採用的理由。

GPT 回覆格式（寫在對應 ID 下的「GPT 回覆」欄；新問題自己編下一號）：
```
看的 commit: <sha>
問題／證據: <哪一站、哪個鏡位、截圖說明>
建議: <下一步>
```

## 每項欄位
- **ID**、**狀態**（待查／處理中／待複核／通過／退回／延後）
- **base commit**：開工前的 commit；**candidate commit**：Claude 改完上線的 commit
- **證據**：同鏡位、同天候的改前／改後真實 WebGL 截圖（遠景、近景、手機 390×844、桌面），以及 check.py 數字
- **結果**、**下一步**、**回退點**（要退回就 `git revert <candidate>`）

## 驗收原則（GPT 2026-11-25 提出，已採用）
- 截圖用無頭 Chrome 軟體渲染（SwiftShader）拍的真實 WebGL 畫面，**不等於手機 GPU 實測**；FPS、記憶體、實機零穿模一律標「未測」。
- 模型數與檔案大小只是預算上限，不能當成手機順暢的證明。
- 語法檢查通過 ≠ 畫質通過；畫質要看前後圖。
- 每項還要確認：路線切換、景點參觀、室內、跨島切換正常，人車數不變。
- 每次小 commit、只同步改到的共享區塊；失敗只撤回自己這一步改的檔，**不用 `git checkout .`**。
