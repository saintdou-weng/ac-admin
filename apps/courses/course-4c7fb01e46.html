3D 是什麼？用座標找到每一個位置

這一課你會學到
  • 1D、2D、3D 的差別
  • X、Y、Z 三個軸代表什麼
  • 為什麼不同軟體「哪個軸朝上」不一樣

從找教室開始

假設你要告訴轉學生怎麼找到你的座位：

  • 只說「第 3 排」，他只知道在哪一排，這是 1 個數字。
  • 說「第 3 排、第 5 個」，他就能找到你。這是 2 個數字，就像地圖上的位置。
  • 如果學校有好幾層樓，你得再加上「3 樓」。這是 3 個數字：左右、前後、上下。

這就是 1D、2D、3D 的差別。3D 世界裡的任何一個位置，都可以用 3 個數字說清楚。電腦裡的 3D 模型，說穿了就是一大堆「用 3 個數字記錄的位置」。

名詞由來：D 與「維度」

3D 是 three-dimensional（三維）的縮寫。Dimension 來自拉丁文 dimensio，意思是「測量」。所以「三維」就是「要測量三個方向」：長、寬、高。

X、Y、Z：三把互相垂直的尺

數學家把這三個方向叫做 X 軸、Y 軸、Z 軸。想像房間的一個牆角：地板和兩面牆交會的那一點叫做原點，座標是 (0, 0, 0)。從原點出發有三條線，彼此互相垂直，每一條都是一把尺。

名詞由來：笛卡兒座標

1637 年，法國數學家笛卡兒（René Descartes）在著作《幾何學》中，把「位置」變成「數字」。傳說他躺在床上看著天花板上的一隻蒼蠅，想到只要知道蒼蠅離兩面牆各多遠，就能準確說出牠在哪裡。這個故事不一定是真的，但他的方法到今天還是 3D 軟體的基礎，所以叫做「笛卡兒座標系」。

互動：移動小球，看它的座標 拖曳可旋轉

兩派人馬：Y 朝上 vs Z 朝上

有一件事會困擾很多新手：不同軟體對「哪個軸是高度」的看法不一樣。

陣營高度用哪個軸代表軟體由來
Y 朝上YThree.js（網頁 3D）、Unity、Maya從電腦螢幕的 2D 畫面延伸：X 是橫、Y 是直，再加一個「往螢幕裡面」的 Z
Z 朝上ZBlender、Unreal、建築 CAD 軟體從建築和工程的平面圖延伸：地圖本來就是 X、Y，高度是後來加上去的 Z

兩派都沒有錯，就像有人習慣靠左走、有人習慣靠右走。重要的是：請 AI 幫忙時，要告訴它你用哪一套。上面的互動圖勾選「改用 Blender 的方向」，你會看到同一顆球在兩種說法下的座標數字不同。

記憶口訣：RGB = XYZ

幾乎所有 3D 軟體都用紅色代表 X、綠色代表 Y、藍色代表 Z。因為電腦顏色的順序剛好是 RGB（Red、Green、Blue），和 XYZ 一一對應。這份教材的顏色也照這個規則。

動手做

把教室或房間的一個牆角當作原點，量一量（或用步伐估算）你的書桌離兩面牆各有幾公尺、桌面有多高，寫成 (X, 高度, 前後) 三個數字。你剛剛完成了人生第一次「3D 測量」。

在 Three.js（網頁 3D）裡，哪一個軸代表「高度」？

答案是 Y 軸。Three.js 屬於「Y 朝上」陣營；Blender 則是 Z 朝上。

本課重點
  • 3D 的每個位置都能用 3 個數字 (X, Y, Z) 表示。
  • 紅綠藍 = X Y Z。
  • Three.js 是 Y 朝上，Blender 是 Z 朝上，跟 AI 溝通時要講清楚。

點、線、面：3D 模型的積木

這一課你會學到
  • 頂點、邊、面、多邊形、網格是什麼
  • 為什麼電腦特別喜歡三角形
  • 面數多和面數少各有什麼好壞

從一個點長成一個方塊

中文英文一句話解釋
頂點Vertex空間中的一個位置，用 (X, Y, Z) 記錄
邊Edge連接兩個頂點的直線
面Face三條以上的邊圍起來的平面
多邊形Polygon面的正式名稱；3D 界常簡稱「poly」

名詞由來

Vertex：拉丁文原意是「轉折處、最高點」，就是線條轉彎的地方。
Polygon：希臘文 poly（很多）+ gōnia（角），意思是「很多角的形狀」。
Mesh：英文本來是「網子」。3D 模型的線框看起來就像一張罩在物體上的漁網，所以這樣叫。

為什麼電腦最愛三角形？

還記得數學課學過的嗎？不在同一直線上的三個點，一定能決定一個平面。三角形永遠是平的，不會歪掉。四邊形就不一定了：把一張紙的四個角隨便抬起一個，它就彎了。

電腦要算光線照在面上的角度，面「一定是平的」會讓計算簡單又穩定。所以不管你在軟體裡做的是四邊形還是更多邊形，顯示卡最後都會把它切成三角形再畫出來。

互動：面數越多，越圓滑 拖曳可旋轉

低面數 vs 高面數

把細分數量拉到 3，球會變成像鑽石一樣的尖角；拉到 48，就很圓了。這就像手機照片的解析度：越高越細緻，但檔案越大、手機越跑不動。

低面數（Low Poly）高面數（High Poly）
看起來有稜有角，風格化圓滑、細節多
電腦負擔輕，手機遊戲也跑得動重，需要好的顯示卡
常見用途手機遊戲、網頁、建築示意電影、公仔、3D 列印

萬物都是基本形

3D 軟體都內建幾種「基本形」（Primitive）：方塊、球、圓柱、圓錐、甜甜圈（圓環）。它們就是你的樂高積木。

名詞由來：Primitive 與塞尚

Primitive 原意是「最原始、最基本的」。畫家塞尚（Paul Cézanne）在 1904 年寫給朋友的信中說，要用圓柱、球體和圓錐來處理自然。一百多年後，3D 建模師還在用同樣的想法：先用基本形抓出大概的樣子，再慢慢修細節。

動手做：用基本形拆解身邊的東西

挑三樣東西，寫出它們是由哪些基本形組成的。例如：

  • 電風扇 = 圓柱（底座）+ 細圓柱（桿子）+ 扁圓柱（馬達）+ 很扁的方塊（扇葉）
  • VRT 廠房 = 大方塊（主廠房）+ 中方塊（倉庫）+ 高方塊（辦公樓）

學會「用基本形看世界」，你就已經具備建模師最重要的眼光。

為什麼顯示卡最後都會把模型切成三角形？

三角形永遠是平的，電腦計算光線、陰影時不會出錯，所以是 3D 繪圖的最小單位。

本課重點
  • 頂點 → 邊 → 面 → 網格，這是 3D 模型的組成方式。
  • 三角形是電腦畫 3D 的最小單位。
  • 面數是「預算」：越多越細緻，也越吃效能。
  • 先用基本形拆解，再修細節。

新手最常見的問題：「我的模型怎麼一片黑？」答案通常是忘了放燈光。就像舞台燈沒開，演員再好看觀眾也看不到。

材質：同樣的形狀，不同的感覺

現代 3D 軟體描述材質，最常用兩個數字，都是從 0 到 1：

  • 粗糙度（Roughness）：0 像鏡子一樣光滑，1 像黑板一樣霧面。
  • 金屬度（Metalness）：0 是塑膠、布料、木頭，1 是金屬。金屬的反光會帶有自己的顏色，例如金子的反光是金色的。

想想 VRT 廠房裡的東西：縫紉機的金屬外殼（金屬度高、粗糙度中）、布料（金屬度 0、粗糙度接近 1）、剛拖過的地板（金屬度 0、粗糙度低）。

兩種攝影機

  • 透視攝影機（Perspective）：近大遠小，跟人眼一樣。拍照片、做遊戲用這個。上面互動的 FOV 滑桿，就是調整鏡頭的「視野角度」：數字大是廣角（看得廣，但邊緣變形），數字小是望遠。
  • 正交攝影機（Orthographic）：沒有近大遠小，遠近的東西一樣大。建築平面圖、工程圖、角色三視圖都用這個，因為可以直接量尺寸。
名詞由來：透視與正交

「透視法」大約在 1415 年由義大利建築師布魯內萊斯基（Filippo Brunelleschi）用鏡子實驗整理出來，文藝復興的畫家從此會畫出有深度的畫。
「正交」（Orthographic）來自希臘文 orthos（直的、正的）+ graphein（畫），意思是「垂直投影的畫法」，是工程製圖的基本功。

渲染：讓電腦「拍照」

擺好模型、材質、燈光、攝影機之後，電腦要計算每一個像素是什麼顏色，這個過程叫做渲染。

  • 即時渲染（Real-time）：一秒算 30 到 60 張以上，遊戲和這份教材的互動圖都是。
  • 離線渲染（Offline）：一張圖可以算好幾分鐘甚至幾小時，動畫電影就是這樣做出來的，所以光影特別真實。
名詞由來：Render 與「渲染」

英文 render 來自拉丁文 reddere，意思是「交出去、呈現出來」。中文翻成「渲染」則借用了國畫技法：用水墨一層層暈開，讓畫面有明暗層次。電腦算出光影明暗，正好很像這件事。台灣業界也常說「算圖」。

建築平面圖要能直接量尺寸，應該用哪種攝影機？

正交攝影機沒有「近大遠小」，所以圖上 1 公分代表的長度到處都一樣，可以量尺寸。聚光燈是燈光，不是攝影機喔。

本課重點
  • 場景 = 模型 + 材質 + 燈光 + 攝影機，最後渲染成圖。
  • 材質靠粗糙度和金屬度描述。
  • 模型一片黑，先檢查燈光。
  • 透視用來看，正交用來量。

AI 是怎麼「會說話」的？

你玩過文字接龍嗎？「今天天氣很……」你會接「好」或「熱」，因為你看過很多這樣的句子。聊天型 AI 的核心叫做大型語言模型（LLM），它讀過非常大量的文字和程式碼，變成一個超級接龍高手：根據前面的內容，一個字一個字地預測接下來最適合說什麼。

因為它讀過大量程式碼和教學文件，所以它也很會「寫程式」和「解釋怎麼操作軟體」。這一點對我們做 3D 非常重要。

名詞由來：AI、LLM、Transformer

AI（Artificial Intelligence，人工智慧）這個詞在 1956 年美國達特茅斯學院的一場研討會上，由電腦科學家麥卡錫（John McCarthy）等人正式提出。
LLM 是 Large Language Model 的縮寫，「大型」指它的參數（可以想成腦中的連結）多到數十億、數千億個。
Transformer 是 2017 年 Google 研究團隊在論文〈Attention Is All You Need〉中提出的架構，現在幾乎所有聊天 AI 都建立在它上面。

認識三位助手

ChatGPT

OpenAI 公司開發，2022 年 11 月推出，讓全世界認識聊天 AI。GPT 是 Generative Pre-trained Transformer 的縮寫：「會生成內容、事先訓練好的 Transformer」。

Claude

Anthropic 公司開發，公司成立於 2021 年。外界普遍認為名字是向「資訊理論之父」克勞德·夏農（Claude Shannon）致敬，他奠定了數位通訊的數學基礎。

Gemini

Google 開發，2023 年 12 月發表。Gemini 是拉丁文「雙胞胎」，也是雙子座。Google 表示這個名字呼應了旗下兩個 AI 團隊（Google Brain 和 DeepMind）合併，也致敬 NASA 的雙子星太空計畫。

AI 給你的程式碼大概會長這樣（每家 AI 寫法略有不同，都沒關係）：

cube.html
<!DOCTYPE html>
<html>
<head>
  <meta charset="utf-8">
  <title>我的第一個 3D 方塊</title>
  <style> body { margin: 0; overflow: hidden; } </style>
</head>
<body>
<script src="https://cdnjs.cloudflare.com/ajax/libs/three.js/r128/three.min.js"></script>
<script>
// 1. 舞台：場景
const scene = new THREE.Scene();

// 2. 觀眾的眼睛：透視攝影機（視角 60 度）
const camera = new THREE.PerspectiveCamera(60, innerWidth / innerHeight, 0.1, 100);
camera.position.set(3, 2, 4);   // 攝影機站在 x=3, y=2, z=4
camera.lookAt(0, 0, 0);          // 看向原點

// 3. 畫家：渲染器，把畫面畫到網頁上
const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.setSize(innerWidth, innerHeight);
document.body.appendChild(renderer.domElement);

// 4. 演員：形狀（1×1×1 的方塊）＋ 戲服（藍色材質）
const cube = new THREE.Mesh(
  new THREE.BoxGeometry(1, 1, 1),
  new THREE.MeshStandardMaterial({ color: 0x2f6fd6 })
);
scene.add(cube);

// 5. 燈光：環境光（陰天）＋ 平行光（太陽）
scene.add(new THREE.AmbientLight(0xffffff, 0.4));
const sun = new THREE.DirectionalLight(0xffffff, 1);
sun.position.set(5, 10, 7);
scene.add(sun);

// 6. 開拍：每一格畫面讓方塊轉一點點
function animate() {
  requestAnimationFrame(animate);
  cube.rotation.y += 0.01;
  renderer.render(scene, camera);
}
animate();
</script>
</body>
</html>

發現了嗎？這段程式碼完全對應第 3 課的舞台劇：場景、攝影機、渲染器、模型加材質、燈光、開拍。以後不管程式碼多長，你都可以用這六個角色去找對應的段落。

名詞由來：0x2f6fd6 是什麼顏色？

電腦顏色常用「十六進位」表示，0x 是「以下是十六進位數字」的記號。後面六個字兩兩一組，分別是紅、綠、藍的量，從 00（沒有）到 ff（最多）。所以 0xff0000 是純紅、0x00ff00 是純綠、0xffffff 是白色。十六進位用 0–9 加上 a–f 共 16 個符號，因為兩位數剛好能表示 0 到 255，符合電腦一個位元組的大小。

小改造挑戰
  1. 把 0x2f6fd6 改成 0xe8a800，方塊會變成工安黃。
  2. 把 BoxGeometry(1, 1, 1) 改成 BoxGeometry(2, 0.5, 1)，它變成什麼形狀？
  3. 把 0.01 改成 0.05，轉速有什麼變化？
  4. 挑戰題：請 AI「在旁邊再加一個紅色的球」，看看它改了哪幾行。
常見錯誤
  • 畫面全白：通常是沒網路，或存檔時變成 cube.html.txt。Windows 請在檔案總管打開「顯示副檔名」檢查。
  • 中文變亂碼：存檔時沒有選 UTF-8。
  • AI 用了 import：新版寫法需要架伺服器，直接雙擊打不開。請 AI「改成不用 import、用 script 標籤載入 r128」。

程式碼裡的 renderer.render(scene, camera) 對應舞台劇的哪一件事？

render 就是渲染：用這台攝影機，把這個場景算成一張畫面。每秒做大約 60 次，就變成動畫。

  • 流程：提示詞 → 複製程式碼 → 存成 .html → 雙擊打開 → 修改。
  • 程式碼的結構 = 場景、攝影機、渲染器、模型、燈光、動畫迴圈。

第四步：檢查三個最常見的錯誤

錯誤 1：建築浮在空中或一半陷在地下

Three.js 的方塊，位置是指它的正中心。高 8 公尺的方塊如果放在 y = 0，會有 4 公尺陷在地底下。
公式：要貼齊地面，y 要設成「高度 ÷ 2」。高 8 的主廠房，y = 4；高 10 的倉庫，y = 5。

錯誤 2：比例怪怪的

在場景裡放一個 1.7 公尺高的小人當「比例尺」，一看就知道門太小、機台太大。專業建築 3D 圖幾乎都會放人形，就是這個原因。

錯誤 3：兩個面重疊時閃爍（Z-fighting）

地板和地面剛好在同一個高度，轉動視角時會一閃一閃的像斑馬紋。這是因為電腦用一個叫深度緩衝（Z-buffer）的東西記錄「誰比較靠近鏡頭」，兩個面距離完全一樣時它決定不了，兩個面就「打架」。英文叫 Z-fighting。解法：把其中一個抬高一點點，例如 0.01 公尺。

  2. 照對話範例，至少再修改 3 次。
  3. 加分題：請 AI 加一台貨車停在裝卸平台旁，或加上幾棵樹（樹 = 圓柱樹幹 + 圓錐樹冠）。
  4. 把每一版存成 vrt_v1.html、vrt_v2.html……改壞了也能回到上一版。

方塊的位置是指正中心，所以 y = 高度 ÷ 2 = 5，底部才會剛好碰到 y = 0 的地面。

本課重點

  • 先做粗模確認比例，細節最後加。
  • 貼地公式 y = 高 ÷ 2；放人形當比例尺；重疊面要錯開。
  • 每一版都存檔，改壞了才能回頭。

三視圖：建模的藍圖

蓋房子要有平面圖，做人物要有三視圖：同一個角色的正面、側面、背面，用正交視角畫，而且每張圖的頭頂、下巴、肩膀、腳底都要在同一條水平線上。有了它，不管是自己建模還是交給圖轉 3D 工具，都不會「正面看是瘦子，側面看是胖子」。

常見錯誤
  • 三個視角不一樣：例如正面有瀏海、背面沒頭髮，或側面變胖。請 AI「只修正側面，讓它和正面一致」，或多生成幾次挑最好的。
  • 有透視、有陰影：圖轉 3D 工具會把陰影當成模型的顏色。提示詞裡一定要寫「均勻光線、沒有陰影」。
  • 手指糊在一起：生圖 AI 常把手畫壞。三視圖可以先接受簡化的手，建模時再修。

T-pose 和 A-pose

三視圖和 3D 模型通常用兩種標準姿勢：

  • T-pose：雙手水平張開，整個人像大寫字母 T，名字就是這樣來的。好處是手臂和身體完全分開，建模、貼材質都方便。
  • A-pose：雙手往下斜 30～45 度，像字母 A。肩膀比較接近自然放鬆的樣子，之後做動畫時肩膀變形比較少，現在很多遊戲公司偏好它。上面的互動圖可以勾選切換。

用三視圖交給圖轉 3D 工具時，為什麼要求「沒有陰影」？

陰影如果被「印」在模型顏色上，換個角度或換個燈光時就會出現不該有的黑塊。

本課重點
  • 頭身比決定風格：Q 版 2～3、日漫少年 6.5 左右、寫實 7～7.5、英雄 8 以上。
  • 先寫角色設定卡，再做三視圖；三個視角要對齊。
  • 生圖要求：正交、白底、均勻光、T-pose 或 A-pose、原創。

美術教室裡的木頭人偶

美術教室常有一種木頭關節人偶：頭是球、身體是橢圓塊、手腳是一節一節的圓柱，關節處可以轉。用程式做人物，第一步就是做一個這樣的人偶。

軸心：手臂要繞著肩膀轉

在 Three.js 裡，一個圓柱預設是繞著自己的正中心旋轉。但手臂應該繞著肩膀轉，而不是繞著手肘轉！解法是：先放一個看不見的「軸心」（Pivot）在肩膀，再把手臂掛在軸心下面。轉軸心，手臂就跟著繞肩膀轉。

名詞由來：Pivot（軸心）

Pivot 原本是法文，指門的「樞軸」：門片繞著它轉。籃球也有這個詞：「軸心腳」就是一腳踩住不動當中心、另一腳轉動，跟 3D 的軸心是同一個意思。

父子關係：肩膀帶動手肘，手肘帶動手掌

抬起上臂時，前臂和手掌會跟著一起移動，這叫父子關係（Parent–Child，也叫階層 Hierarchy）。上臂是「父」，前臂是「子」，手掌是「孫」。子物件會跟著父物件動，但也可以自己再轉（例如彎手肘）。

動畫：關鍵影格和中間張

動畫是一張一張的圖快速播放，電影通常是每秒 24 張（24 fps），因為這是人眼覺得流暢、又最省底片的數字。

名詞由來：關鍵影格（Keyframe）

早期迪士尼的手繪動畫，資深動畫師只畫最重要的幾張姿勢，叫「關鍵張」（key frame）；再由助手畫中間的過渡，叫「中間張」（in-between）。3D 動畫也一樣：你只要設定幾個關鍵姿勢，電腦會自動算出中間的過渡，這叫補間（tweening，來自 in-between）。

走路循環（Walk Cycle）是動畫師的基本功：左腳前、雙腳交錯、右腳前、雙腳交錯，四個關鍵姿勢一直重複。手臂和腳的方向相反（左腳在前時右手在前），這樣身體才會平衡。上面的互動模型就是這樣做的：腿用 sin 函數前後擺，手臂用負的 sin 反方向擺，膝蓋在腳往後時彎曲。

- 身體：藍綠色無袖球衣（方塊）、同色短褲
- 手腳：每一肢分兩節（上臂／前臂、大腿／小腿），用圓柱做
- 每個關節都要有 Group 當軸心：肩、肘、髖、膝。圓柱往下掛在軸心下面，讓它繞關節轉

常見錯誤
  • 手臂繞著中間轉，像風車：忘了做軸心。請 AI「每個關節用 Group 當軸心，圓柱往下移動一半長度」。
  • 彎膝蓋時小腿飛走：小腿沒有放在大腿的軸心「裡面」，父子關係錯了。
  • 走路像機器人：只有腿在動。加上手臂反向擺、身體上下微微起伏，就會自然很多。

要讓手臂繞著肩膀轉，而不是繞著手臂中間轉，應該怎麼做？

物件預設繞自己的中心轉。先在關節放軸心，把手臂往下移一半長度放進去，轉軸心就是繞關節轉。

本課重點
  • 關節 = 軸心；肢體掛在軸心下面。
  • 骨架是父子關係的樹，骨盆是根。
  • 骨架、綁骨、蒙皮、權重讓一整張皮跟著骨頭自然變形。
  • 動畫 = 關鍵影格 + 電腦補間；走路時手腳反向。

  • 用手機拍照掃描的拍攝要領

做動漫角色可以靠想像，做真人就不一樣了：每個人的臉都很獨特，差一點點就「不像」。所以真人 3D 通常不是從零開始捏，而是從真實世界「拍」下來。

四種方法

方法怎麼做需要什麼由來
攝影測量繞著人拍幾十到上百張照片，軟體找出照片之間相同的點，算出 3D 形狀手機＋攝影測量 App 或軟體Photogrammetry：photo（光）＋ gram（記錄）＋ metry（測量），「用照片來測量」。原本用在空拍製作地圖

手機拍照掃描的拍攝要領

  1. 光線要均勻：陰天戶外或室內多盞燈最好，避免強烈陽光造成硬影子。
  2. 被拍的人不能動：坐在椅子上最穩。眼睛看固定一點，表情放鬆。
  3. 繞一圈拍三層：從腰的高度、眼睛高度、稍微從上往下各繞一圈，每一步大約轉 10～15 度。
  4. 相鄰照片重疊六到八成：軟體要靠「相同的點」拼起來，重疊太少就拼不起來。
  5. 避開反光和透明：眼鏡摘掉，亮面的衣服和飾品盡量避免；頭髮越蓬越難掃。

掃描完的模型通常有幾十萬個三角面、表面有破洞和雜點，還需要修模、減面、重新拓撲。這些是第 12、13 課的內容。

AI 能幫什麼

把上面的要領交給 AI，請它依你的器材客製化：

拍攝規劃提示詞
我想用手機攝影測量掃描自己的上半身做成 3D 公仔。器材：一支手機、一張椅子、客廳兩盞燈，有一位朋友幫我拍。
請給我：1. 拍攝前的準備清單 2. 拍攝路線（幾圈、幾張、什麼高度）3. 最容易失敗的 5 個原因和預防方法。用國中生看得懂的中文。
一定要知道：肖像權和同意
  • 只掃描自己，或已經同意的人。每個人對自己的臉和形象都有權利（肖像權）。未成年人要掃描，請讓家長知道並同意。
  • 不要用真實名人的臉做 3D 並公開或販售。名人的形象也受保護，拿來做商品或假影片可能違法，也會傷害本人。
  • 不要做「假冒真人」的內容。用別人的 3D 臉做出他沒說過的話、沒做過的事（深偽，Deepfake），可能構成詐騙或誹謗。
  • 掃描檔也是個人資料。別人的臉部模型不要隨便上傳到不熟悉的網站。

用攝影測量掃描時，為什麼相鄰的照片要重疊六到八成？

攝影測量是靠同一個點在不同照片裡的位置差異算出深度，重疊太少就找不到對應點。

本課重點

  • 均勻光、不動、繞三圈、重疊六到八成、避開反光。
  • 只掃自己或同意的人；不拿名人的臉做公開或商業用途。

Blender ＋ AI：讓 AI 寫腳本幫你建模

這一課你會學到

  • 用 AI 寫 Python 腳本，一鍵生出 VRT 廠房

名詞由來：Blender 和 Python

Blender：1990 年代荷蘭一家動畫公司 NeoGeo 內部開發的工具，主要開發者是羅森達爾（Ton Roosendaal）。名字取自瑞士電子樂團 Yello 的一首歌。後來公司倒閉，2002 年社群發起募款，大約七週就湊到 10 萬歐元把它「贖回來」並開放原始碼。從此 Blender 永遠免費，也成為全世界最多人用的 3D 軟體之一。
Python：1991 年由荷蘭程式設計師范羅蘇姆（Guido van Rossum）發表。名字不是蟒蛇，而是他喜歡的英國喜劇團體「Monty Python」。它語法簡單，是很多人學的第一個程式語言。

為什麼要學 Blender？

網頁 3D（Three.js）適合展示，但要做精細模型、動畫、輸出給遊戲或 3D 列印，業界會用專業軟體。Blender 免費、功能完整，而且內建 Python：幾乎所有按鈕都能用程式碼操作。這代表 AI 可以寫腳本幫你一口氣完成很多重複的步驟。

介面的四個區域

區域位置（預設）做什麼
3D 視窗中間最大的一塊看模型、選取、移動

基本操作：按住滑鼠中鍵拖曳是旋轉視角，滾輪是縮放，Shift＋中鍵是平移。記得：Blender 是 Z 朝上（第 1 課）。

用腳本一鍵蓋廠房

  1. 到 Blender 官網（blender.org）下載安裝，打開後先按 A 全選、X 刪除預設方塊。
  2. 點上方的「Scripting」分頁，中間會出現文字編輯區。
  3. 按「New」新增一個文字檔，把 AI 給的腳本貼上。
  4. 按 ▶（Run Script）或 Alt＋P 執行。
  5. 切回「Layout」分頁，看你的廠房。

def box(name, sx, sy, sz, x, y, mat):
    # 先建 1×1×1 的方塊，再用縮放變成需要的尺寸
    # z 放在 sz/2，底部才會貼齊地面（第 7 課的公式）
    bpy.ops.mesh.primitive_cube_add(size=1, location=(x, y, sz / 2))
    o = bpy.context.active_object
    o.name = name
    o.scale = (sx, sy, sz)
    o.data.materials.append(mat)
    for c in o.users_collection:
        c.objects.unlink(o)
    col.objects.link(o)
    return o

注意到了嗎？座標換了

Three.js 版本裡辦公樓在 z = −9，Blender 版本在 y = 9。因為 Blender 是 Z 朝上，Three.js 的「前後」（Z）變成了 Blender 的 Y，而且方向相反。這就是第 1 課一再強調要告訴 AI 座標系統的原因。

常見錯誤：版本不同

Blender 每年都會更新，有些指令的名字會改。如果執行後下方出現紅字（例如 AttributeError 或 KeyError），這樣處理：

  1. 選單「Window → Toggle System Console」（Windows）打開完整錯誤訊息。
  2. 把錯誤訊息整段複製給 AI，並告訴它：「我的 Blender 版本是 4.x」（版本號在 Blender 啟動畫面或「Help → About」可以看到）。
  3. 請 AI 給你完整的修正版，而不是只改一行。
動手做：從粗模到有細節

Blender 腳本執行出現紅字錯誤，最有效的做法是？

錯誤訊息會告訴 AI 是哪一行、哪個指令出問題，加上版本號，它就知道要換成新版的寫法。

專業概念：細分、拓撲、法線、UV 與 PBR

這一課你會學到
  • 怎麼用少少的面做出圓滑的模型
  • 什麼是「好的拓撲」
  • 法線翻轉造成的黑洞
  • UV 展開，以及它和成衣打版的關係
  • PBR 材質的幾張貼圖

細分曲面：用粗網格控制圓滑的形狀

專業建模師不會一開始就做幾十萬面。他們先做一個面數很少的「籠子」，再讓電腦自動把每個面切成四個、把角磨圓，重複幾次就變得很光滑。這叫細分曲面（Subdivision Surface）。

名詞由來：Catmull–Clark

目前最常用的細分方法，是 1978 年由卡特莫爾（Edwin Catmull）和克拉克（Jim Clark）發表的。卡特莫爾後來成為皮克斯動畫工作室的共同創辦人，皮克斯的角色就大量使用細分曲面。在 Blender 裡，它是一個叫「Subdivision Surface」的修改器。

拓撲：線要怎麼走

拓撲（Topology）指的是網格裡的點、線、面「怎麼連接」，也就是線的走向。兩個模型外型一樣，拓撲可能完全不同。好的拓撲有幾個特徵：

  • 以四邊形為主：細分和彎曲時最穩定（最後顯示卡還是會切成三角形）。
  • 邊流沿著肌肉和結構走：臉上的線要繞著眼睛和嘴巴轉圈，像水波一樣。這叫邊流（Edge Flow）。
  • 要彎的地方多幾條線：手肘、膝蓋、手指關節處要有 3 條左右的環狀線，彎起來才不會像吸管折到。
  • 不需要的地方少一點：平平的背部不用太多面。
名詞由來：拓撲

來自希臘文 topos（地方）＋ logos（學問），原本是數學的一個分支，研究「形狀怎麼連接」而不管它的大小。中文「拓撲」是音譯。數學家有個有名的笑話：在拓撲學家眼中，甜甜圈和馬克杯是一樣的，因為它們都只有一個洞。

把掃描或 AI 生成的亂七八糟網格，重新做成乾淨拓撲的過程，叫做重新拓撲（Retopology，常簡稱 retopo）。這是專業人物建模很重要的一步。

法線：面的正面朝哪裡

每個面都有「正面」和「背面」。從正面垂直往外指的那個方向，叫做法線（Normal）。電腦用法線判斷光從哪個角度照到這個面，所以法線決定明暗。

名詞由來：Normal（法線）

拉丁文 norma 是木匠用的直角尺。所以 normal 在數學裡的意思是「垂直的」，跟「正常」的意思是後來才衍生的。

常見錯誤：模型上出現黑洞或看不見的面

如果有些面的法線朝內（翻轉了），在網頁 3D 裡它們可能會消失，在 Blender 裡則會顯得很黑。解法：在 Blender 的編輯模式全選，按 Shift＋N「重新計算法線」。從別處匯入的模型特別常見這個問題。

UV 展開：就是成衣打版

要把一張 2D 的圖片（例如球衣上的號碼、布料花紋）貼到 3D 模型上，電腦得知道「模型上的每一點對應到圖片上的哪一點」。做法是把 3D 模型的表面剪開、攤平成 2D，這叫 UV 展開。

在 VRT 工作過的人一聽就懂：這就是打版的反過來。打版是把 2D 的布片縫成立體的衣服；UV 展開則是把立體的模型拆回平面的版片。剪開的那條線，3D 界也叫做縫線（Seam）。國中數學的「正方體展開圖」就是最簡單的 UV 展開：

名詞由來：為什麼叫 UV？

因為 X、Y、Z 已經被 3D 空間用掉了！2D 圖片也需要兩個座標軸，於是就用字母表中 X 前面的 U 和 V。（有時還會用到 W。）

常見錯誤：貼圖拉伸、接縫明顯

版片攤得不平，圖案就會被拉長或擠在一起；縫線放在正面，接縫就很明顯。原則跟做衣服一樣：縫線藏在不顯眼的地方（腋下、側邊、背後），版片盡量攤平不變形。

PBR：像真的一樣的材質

第 3 課學過粗糙度和金屬度。專業模型會用好幾張貼圖（Texture），讓模型每一點都有不同的數值：

貼圖記錄什麼例子
顏色貼圖（Base Color）表面本來的顏色，不含光影球衣的藍綠色和號碼
粗糙度貼圖哪裡亮滑、哪裡霧面鞋子的亮面皮革和霧面鞋底
金屬度貼圖哪裡是金屬縫紉機的金屬壓腳
法線貼圖（Normal Map）假裝有凹凸的細節，不必真的多做面布料的織紋、牆面的磚縫
名詞由來：PBR

Physically Based Rendering，「以物理為基礎的渲染」。依照真實世界光的物理規律計算材質。2012 年迪士尼公開了一套易用的材質原則，之後幾年遊戲業和電影業普遍採用，Blender 的「Principled BSDF」材質就是這套想法。

UV 展開最像成衣廠的哪一項工作？

打版是把立體的衣服拆成平面版片的學問，UV 展開也是把立體模型剪開攤平，連「縫線」這個詞都一樣。

本課重點
  • 細分曲面：少少的面控制圓滑的形狀。
  • 好拓撲：四邊形為主、邊流順著結構、關節多加線。
  • 黑洞通常是法線翻轉，重新計算法線。
  • UV 展開 = 打版的反過來；縫線藏好。
  • PBR 用多張貼圖描述每一點的顏色、粗糙度、金屬度和細節。

AI 圖轉 3D：從一張圖到可用的模型

這一課你會學到
  • 「文字 → 圖 → 3D → 修模」的完整流程
  • 三個 AI 和圖轉 3D 工具怎麼分工
  • 怎麼檢查一個 AI 生成的模型能不能用

近幾年出現很多「上傳一張圖，幾分鐘就變成 3D 模型」的線上工具（例如 Meshy、Tripo 這類服務，名稱、價格和免費額度變化很快，請自行搜尋最新的）。它們讓人物建模的門檻大幅降低，但產出的模型通常還不能直接用。這一課教你把它變成真正能用的模型。

完整流程

  1. 寫角色設定卡第 8 課。可以請 Claude 幫你把設定整理成精準的生圖提示詞。
  2. 生成三視圖或正面立繪用 ChatGPT 或 Gemini。白底、均勻光、T-pose 或 A-pose。
  3. 上傳到圖轉 3D 工具有「多視角輸入」就放三視圖，結果通常比單張圖好。
  4. 匯入 Blender 檢查用下面的檢查清單一項一項看。
  5. 清理和減面刪掉雜點、補洞，把面數降到用途需要的程度。
  6. 重新拓撲（需要動畫時）做出乾淨的四邊面，關節多加線。
  7. UV 與材質修正糊掉的貼圖，重畫需要清楚的地方（例如背號）。
  8. 綁骨與動畫可以先用自動綁骨服務（例如 Adobe 的 Mixamo）試試，再用 Blender 微調權重。
  9. 匯出依用途選格式，第 14 課。
名詞由來：Decimate（減面）

Blender 的減面修改器叫 Decimate。這個字來自拉丁文 decimare，原意是古羅馬的「十中取一」，後來變成「大量減少」的意思。減面就是在盡量不改變外型的前提下，把面數大幅降低。

檔案格式與輸出：網頁、遊戲、3D 列印、建築

這一課你會學到
  • 四種最常見的 3D 檔案格式和它們的由來
  • 不同用途要選哪一種
  • 單位換算的陷阱、3D 列印的「水密」、建築的 BIM

就像照片有 JPG、PNG，文件有 DOCX、PDF，3D 模型也有很多格式。每一種都是為了某個目的誕生的。

格式全名與由來能存什麼最適合
.obj1980 年代 Wavefront Technologies 公司為自家動畫軟體設計的格式，簡單又通用形狀、UV；材質另存成 .mtl在不同軟體之間交換靜態模型
.fbxFilmbox，原本是加拿大 Kaydara 公司的動作捕捉軟體，2006 年被 Autodesk 收購形狀、材質、骨架、動畫遊戲引擎（Unity、Unreal）、動畫
.gltf / .glbGL Transmission Format，由制定 OpenGL 的 Khronos Group 在 2015 年推出，號稱「3D 界的 JPEG」。.glb 是把所有東西打包成一個檔形狀、PBR 材質、骨架、動畫網頁、手機 AR、Three.js
.stlStereolithography（立體光刻），1987 年 3D Systems 公司為第一代 3D 列印機設計只有形狀（三角面），沒有顏色3D 列印

依用途選格式

放在網頁上

選 .glb。Three.js 用 GLTFLoader 載入。檔案盡量小，建議先減面、壓縮貼圖。

放進遊戲引擎

選 .fbx 或 .glb。注意 Blender（Z 朝上）和 Unity（Y 朝上）的座標轉換，匯出時有選項。

3D 列印成公仔

選 .stl（或 .3mf）。模型必須「水密」，而且單位要是公釐。

廠房設施管理

專業建築用 BIM 軟體和 .ifc 格式，模型裡不只有形狀，還有設備資料。

常見錯誤：單位差了 1000 倍

Blender 預設用公尺，3D 列印軟體大多用公釐（mm）。一個 0.2 公尺高的公仔，如果匯出時沒換算，列印軟體會以為它只有 0.2 公釐，小到看不見。反過來也會出現「公仔比房子還大」。匯出前先確認：1 公尺 = 1000 公釐，並在匯出設定中調整比例。

名詞由來：水密（Watertight）

原本是造船用語：船身沒有任何縫隙，水進不來。3D 列印需要模型像一艘船一樣完全封閉，沒有破洞、沒有兩個面沒接好的縫，列印機才分得清楚「哪裡是裡面、哪裡是外面」。也叫做「流形」（Manifold）。

名詞由來：BIM 與 IFC

BIM 是 Building Information Modeling，「建築資訊模型」。它不只是建築的 3D 外型，每一根柱子、每一台設備都帶有資料：材質、規格、廠商、保養日期。
IFC 是 Industry Foundation Classes，一種開放的 BIM 交換格式，讓不同公司的軟體能互相讀取。
對工廠來說，把縫紉機、空壓機、消防設備都放進 BIM 模型，就能在 3D 裡查詢每一台設備的資料，這是走向「數位雙胞胎」的第一步（第 16 課）。

想把阿勇放在網頁上，用 Three.js 顯示，最適合的格式是？

.glb 一個檔就包含形狀、材質、骨架和動畫，是網頁 3D 的標準格式。.stl 沒有顏色，是給 3D 列印用的。

本課重點
  • 網頁 .glb、遊戲 .fbx／.glb、交換 .obj、列印 .stl、建築 BIM／.ifc。
  • 匯出前確認單位和座標朝向。
  • 3D 列印的模型要水密。

專業工作流與除錯大全

這一課你會學到

  • 面數預算和 LOD
  • 和 AI 長期合作的規矩
  • 一張「看症狀、找原因、跟 AI 怎麼說」的除錯表

專業 3D 製作流程

不管是遊戲公司、動畫公司還是建築事務所，流程大同小異。括號是對應的課：

  1. 需求與參考做給誰看？用在哪裡？收集參考照片、尺寸圖。（第 5、7 課）
  2. 概念設計角色設定卡、三視圖、建築平面圖。（第 7、8 課）
  3. 粗模用基本形確認比例和構圖。（第 2、7 課）
  4. 細模加上細節，細分曲面或雕刻。（第 12 課）
  5. 拓撲重新拓撲成乾淨、面數合適的網格。（第 12、13 課）
  6. UV 與材質展開、畫貼圖、PBR 材質。（第 12 課）
  7. 骨架與動畫綁骨、蒙皮、關鍵影格。（第 9 課）
  8. 燈光與渲染擺燈、擺鏡頭、算圖。（第 3 課）
  9. 輸出與交付選對格式和單位。（第 14 課）

建築類通常停在第 6 步再接第 8、9 步（建築不用骨架）；人物類則全部都要走。

面數預算和 LOD

就像零用錢要分配，面數也要分配。一般來說，手機遊戲的角色常在幾千到兩萬個三角面左右，電腦和主機遊戲的主角可以到幾萬甚至十萬以上，電影角色則可以高得多（因為是離線渲染）。實際數字依專案而定，重要的是先問清楚用途，再決定預算。

名詞由來：LOD

Level of Detail，「細節層級」。同一個模型準備好幾個版本：鏡頭靠近時用高面數，遠遠一個小點時換成低面數，觀眾看不出差別，電腦卻省下很多力氣。VRT 廠區如果要做成網頁導覽，遠處的縫紉機就可以只用一個方塊代表。

和 AI 長期合作的五條規矩

  1. 存版本。每一版都存檔（v1、v2、v3）。AI 改壞了，你能退回上一版。專業團隊會用 Git 這類「版本控制」工具做同樣的事。
  2. 先說計畫，再動手。複雜修改先請 AI「用條列說明你打算改哪裡」，你確認後再給程式碼。
  3. 一次一件事。第 5 課學過，到專業階段更重要。
  4. 自己驗證。AI 說「已經對齊地面」，你要轉過去看；說「尺寸是 60 公尺」，你要量。AI 會犯錯，也可能很有自信地說錯。
  5. 對話太長就重開。把「目前規格＋最新程式碼」整理好，貼進新的對話繼續。

三選一畢業專案

A　VRT 廠區數位雙胞胎

用 Three.js 或 Blender 做出完整廠區：鋸齒屋頂、12 條縫紉線、倉庫、辦公樓、道路。點擊每條縫紉線，會顯示它的名稱和一段說明。

B　原創角色動起來

設計自己的原創角色：設定卡、三視圖、3D 模型（程式組裝或圖轉 3D 後修模），至少有走路和一個招牌動作，匯出成 .glb 放上網頁。

C　自己的 3D 公仔

用攝影測量掃描自己的上半身，清理、減面、補洞，做成水密模型，匯出 .stl。有機會的話送去 3D 列印。

名詞由來：數位雙胞胎（Digital Twin）

在電腦裡做一個和真實工廠、機器「一模一樣」的虛擬分身，並且讓它跟著現實的資料一起變化，例如哪條線正在生產、哪台機器需要保養。這個概念在 2002 年前後由美國學者葛理夫斯（Michael Grieves）提出，後來 NASA 在太空任務中推廣這個名稱。專案 A 就是數位雙胞胎的起點：先有準確的 3D 模型，之後才能接上真實資料。
