給不會寫程式、但想讓工廠變聰明的人

用 Claude
把成衣廠搬上網

從「AI 是什麼」開始，一路學到自己做出產量登記頁、接上雲端、讓 Telegram 機器人自動通知，最後讓 Claude 當你的 24 小時助理。全部用 VRT 的真實工作當例子，國中生也看得懂。

五個階段，像員工升職一樣

  1. 學徒：認識 AIAI 和 Claude 是什麼、怎麼跟它說話、它有哪些工具。
  2. 車工：做出第一個工具為什麼要線上化、資料怎麼整理、網頁怎麼組成，親手做出「車縫日產量登記頁」。
  3. 組長：接上雲端與機器人資料存哪裡、Google Apps Script、Telegram 機器人審核、用 GitHub 發布上線。
  4. 技術員：做對、做穩工廠數字的正確算法（加權效率）、常見錯誤和除錯方法。
  5. 廠長：系統思維與自動化讓 Claude 當代理人自動做事、Factory OS 架構、安全與交接，最後完成畢業專題。
怎麼用這份教材

一次讀一課，大約 15～25 分鐘。每課都有：生活比喻（先懂概念）、VRT 現場（看真的怎麼用）、名詞由來（知道這個字從哪來，就不會忘）、動手試試（可以點、可以玩）、小測驗。看到可以點開看解釋。讀完按「我學會了」，左邊的縫線就會縫實一段。

開始第一課 先看名詞辭典

工序 01｜學徒

AI 是什麼？Claude 是誰？

這課學完，你能用一句話跟同事解釋 Claude，並知道它擅長什麼、哪裡要小心。

生活比喻

想像工廠來了一位新同事：他讀過全世界數不清的書、會中文、英文、高棉文，會寫文章、算數、寫程式，而且 24 小時不用休息。

但是——他從來沒進過 VRT 的廠房。他不知道你們有幾條線、款號怎麼編、組長叫什麼名字。你不告訴他，他就只能猜。Claude 就是這樣的新同事。

AI 到底是怎麼「想」的？

是「人工智慧」。Claude 屬於其中一種，叫做。它的核心本事其實很像一個遊戲：猜下一個字。

你說「今天車縫三線的產量……」，它讀過太多類似的句子，所以知道後面很可能接「是 1,240 件」「比昨天高」這類的字。它一個字一個字地猜，猜得非常準，準到看起來像在思考。

AI 讀文字時，不是一個字一個字讀，而是切成小塊，叫做 。試試看：

動手試試：Token 切字機（示意）
大約 0 個 Token。真正的切法更複雜，這裡只是讓你看個概念：中文常常一兩個字一塊，英文長單字會被切成幾段。Token 也是 AI 計算「用了多少量」的單位。

Claude 擅長什麼？哪裡要小心？

擅長（放心交給它）要小心（你一定要檢查）
寫公告、Email、報告初稿數字計算：它可能算錯，要抽查
中英高棉三語翻譯會「一本正經地胡說八道」，叫做
整理 Excel、找出異常它不知道 VRT 內部資料，除非你給它
寫網頁程式、做小工具法規（例如柬埔寨勞工法）要再查證
解釋看不懂的東西跟錢、人事有關的決定，最後要人拍板
VRT 現場

VRT 約 512 位員工、11～12 條車縫線。過去每天的車縫日報、裁剪報表、採購申請、請假單都靠紙本和 Excel 傳來傳去。現在這些事情大部分都能請 Claude 幫忙：做成網頁表單、自動加總、自動翻成高棉文、自動發 Telegram 通知。做這些系統的人不需要會寫程式——只要會把事情講清楚。這就是這門課要教你的。

Claude 有大、中、小三種腦袋

Claude 有不同型號，常見的名字是 Opus、Sonnet、Haiku。越大的越聰明、越適合難題；越小的越快、適合簡單大量的工作。型號會隨時間更新，但這三個名字的由來很有趣：

Opus（大）拉丁文「作品」，音樂家的大型作品編號就叫 Opus。適合：設計整個系統、分析複雜報表。
Sonnet（中）十四行詩，莎士比亞寫過很多。適合：日常大多數工作。
Haiku（小）日本俳句，只有短短 17 個音。適合：快速分類、簡短回覆。

三個名字都是「詩和作品的長度」——從長篇巨作到短短一句，剛好對應模型的大小。

名詞由來

AI（人工智慧）：1956 年，一群科學家在美國達特茅斯學院開會，約翰‧麥卡錫提出了 artificial intelligence 這個詞。artificial 來自拉丁文「技藝 + 做出來」，意思是「人做出來的」。

Anthropic：做出 Claude 的公司。名字來自希臘文 anthropos「人」，意思是「跟人類有關的」——這家公司強調 AI 要對人類安全、有益。

Claude：一般認為是向「資訊理論之父」克勞德‧夏農（Claude Shannon）致敬，他在 1948 年證明了所有資訊都能變成 0 和 1。

重點回顧

  1. Claude 像一位很聰明、但沒來過你工廠的新同事。
  2. 它的原理是「猜下一個字」，文字會被切成 Token。
  3. 文字工作放心交給它；數字、法規、錢和人的決定，一定要人檢查。

小測驗：Claude 算出「本週全廠效率 97%」，但你覺得太高了。最好的做法是？

答案是 B。AI 可能算錯，但它非常擅長「把過程攤開」。請它一步步列出來，你抽查幾個，就能又快又準。完全不用（C）太可惜了。

工序 02｜學徒

提示詞：跟 Claude 說話的藝術

學會寫出「一次就讓 Claude 聽懂」的指令，這是整門課最重要的基本功。

生活比喻

去飲料店說「給我一杯飲料」，店員只能亂猜。說「大杯珍珠奶茶、半糖、少冰」，一次就拿到你要的。

跟 Claude 說的話，叫做。說得越清楚，結果越好。

好提示詞的五個零件

把它想成一張生產工單：工單寫不清楚，產線一定做錯。

零件問自己VRT 例子
角色它要扮演誰？你是 VRT 成衣廠的人資助理
任務要做什麼？寫一則全廠公告：本週六加班到 17:00
背景它需要知道什麼？員工約 500 人，多數看高棉文
格式成品長什麼樣？中英高棉三語，每種不超過 5 行
限制有什麼不要？用詞簡單，不要提到沒確定的加班費金額
不好的提示詞「寫個加班通知」
結果：可能是英文、可能太長、可能亂寫加班費。
好的提示詞「你是 VRT 人資助理。寫一則全廠公告：本週六加班到 17:00。讀者是約 500 位柬埔寨員工。請用中、英、高棉三語，每種不超過 5 行，用詞簡單。」
結果：一次就能貼到公告欄。
動手試試：提示詞組裝機





四個讓結果更好的小技巧


    

  1. 給範例：貼一份舊的報表或公告，說「照這個格式」。範例勝過千言萬語。
    2. 

  2. 請它先問你：加一句「資訊不夠就先問我」，它會回頭確認，而不是亂猜。
    3. 

  3. 一次一件事：大工作拆成小步驟，一步做完、檢查、再下一步。
    4. 

  4. 像打樣一樣修改：第一版不完美很正常。就像成衣打樣：打樣、看、修改、再打樣。直接說「第 2 段太長，改成 3 行」。
    5. 




名詞由來

Prompt（提示）來自拉丁文 promptus「準備好、拿出來」。在劇場裡，躲在舞台邊小箱子裡、演員忘詞時小聲「提詞」的人，就叫 prompter（提詞人）。你寫提示詞，就是在當 Claude 的提詞人。


還有一個跟成衣廠有關的秘密：英文 text（文字）和 textile（紡織品）來自同一個拉丁字 texere「編織」。古人覺得寫文章就像織布——字是線，文章是布。



重點回顧
    

  1. 提示詞 = 給 Claude 的工單：角色、任務、背景、格式、限制。
    2. 

  2. 給範例、請它先問、一次一件事。
    3. 

  3. 修改就像打樣，直接指出哪裡要改、改成怎樣。



小測驗：下面哪一句最像「好提示詞」？




C 有角色、任務、背景（第 38 週日報）、格式（表格 + 3 句總結）。「要很專業」聽起來有要求，其實 Claude 不知道你說的專業是什麼。

Claude 的工具箱

生活比喻

車縫部有平車、拷克車、雙針車、打結車……每台車做不同的事。Claude 也一樣，同一個腦袋，搭配不同「車台」就能做不同的工作。

VRT 現場

一個好習慣：每個系統開一個專案，例如「VRT 生產平台」「行政中心 HRA」。專案說明裡寫清楚：資料欄位、計算規則、三語要求、「只收完整檔案」等規矩。這樣以後每次開新對話，Claude 都已經「上過新人訓練」了，不用每次重講。

    •

小心

AI 產品更新很快，按鈕位置和功能名稱可能會變。遇到找不到的功能，直接問 Claude，或查官方說明 support.claude.com。



名詞由來

Artifact：拉丁文 arte（用技藝）+ factum（做成的）＝「人用手藝做出來的東西」。考古學家挖到的陶罐就叫 artifact。在 Claude 裡，指它幫你做出來的成品。


MCP：Model Context Protocol，2024 年底由 Anthropic 公開的標準，常被比喻成「AI 的 USB-C 萬用插頭」——不同的服務只要做一個插頭，AI 就都能接上。Protocol 原本是希臘文「黏在卷軸第一頁的說明」，後來變成外交禮儀，再變成電腦之間的溝通規則。



重點回顧
    

  1. 同一個 Claude，搭配不同工具做不同的事。
    2. 

  2. 每個系統開一個專案，把規則寫進去。
    3. 

  3. 文字用聊天、工具做 Artifact、正式文件用檔案、重複工作交給代理人。



小測驗：你希望每次問 Claude 生產問題時，它都自動知道「VRT 有 12 條線、效率怎麼算」。應該用？




A。專案就像部門文件櫃，放一次、一直有效。








工序 04｜車工
為什麼要線上化？
看懂「紙本流程」和「線上流程」差在哪，分清楚數位化、線上化、自動化。



生活比喻

上課傳紙條：寫好、傳給隔壁、再傳、再傳……傳到最後一排可能已經下課了，中間還可能被偷看、弄丟、寫錯。換成班級群組：一發出去，全班同時看到。



一份車縫日報的旅程


VRT 現場

紙本流程


組長手寫›交給文員›打進 Excel›寄 Email›主管下載、手動加總隔天才知道


線上流程


組長用手機輸入›自動存到雲端、自動加總›機器人發 Telegram幾秒鐘


紙本流程每多一手，就多一次打錯、漏掉、延遲的機會。



三個台階：數位化、線上化、自動化




數位化紙變檔案。例：把手寫日報打成 Excel。


線上化大家在網路上用同一份。例：組長手機填、主管同時看到。


機器自己跑。例：每天 17:00 自動彙整、自動發報告、異常自動警告。





線上化的四個好處


    

  • 快：數字即時出現，早上就能發現昨天哪條線落後。
    • 

  • 準：電腦加總不會按錯計算機；欄位可以設定「只能填數字」。
    • 

  • 查得到：誰、什麼時候、改了什麼，都有紀錄。驗廠時很好用。
    • 

  • 省：少印紙、少跑腿、文員可以做更有價值的事。
    • 




小心

有一句話要記住：把亂的流程數位化，只會得到更快的亂。動手做系統之前，先用紙筆把流程畫出來：誰填、誰看、誰核准、多久一次。流程順了，再請 Claude 做系統。



名詞由來

Automation（自動化）：1946 年，美國福特汽車的副總裁德爾瑪‧哈德讓這個詞流行起來，用來形容工廠裡零件自己在機器之間移動。字根是希臘文 automatos「自己動的」。



重點回顧
    

  1. 紙本流程手越多、錯越多、越慢。
    2. 

  2. 數位化 → 線上化 → 自動化，一步一步來。
    3. 

  3. 先理順流程，再做系統。



小測驗：「組長用手機填日報，主管在辦公室同時看到」屬於哪個台階？




B。大家在網路上共用同一份資料就是線上化。如果系統每天 17:00 自己彙整、自己發報告，那才是自動化。








工序 05｜車工
資料：表格就是工廠的記憶
看懂表格的「列」和「欄」，學會好資料的三條規則，親手清洗一份亂資料。



生活比喻

班上的點名簿：一橫列是一個人，一直欄是一個項目（座號、姓名、出席）。工廠的每一種紀錄，都可以整理成這樣的表格。



車縫日報，變成表格長這樣




日期線別款號產量（件）人數工時


2026-09-21Line 3VR22011240388


2026-09-21Line 5VR2201980348

每一列是「某天某條線的一筆紀錄」，每一欄是一種資訊。這種表格叫，Excel 和 Google Sheets 都是。



好資料的三條規則


    

  1. 一格只放一件事：不要在產量格寫「1240（有 20 件重工）」，重工另開一欄。
    2. 

  2. 同一件事，同一種寫法：「L3」「line 3」「3線」電腦會以為是三條不同的線。VRT 的規定是一律寫成「Line 3」。
    3. 

  3. 每筆要有身分證：像員工有工號一樣，每筆資料要有一個不會重複的編號，叫做「主鍵」。名字會重複，工號不會。
    4. 




動手試試：資料清洗機


這是從不同組長收來的原始資料。看看哪裡亂，然後按「開始清洗」。









VRT 現場

VRT 平台裡真的有這幾條「清洗規則」：線別一律統一成「Line N」；表格最下面的「合計」列要排除（判斷方法：款號和客戶都是空白），不然總數會被算兩次。這些規則是踩過坑才寫下來的——你以後也會有自己的規則清單。



名詞由來

Spreadsheet（試算表）：以前會計師把帳目「攤開（spread）」在一張跨兩頁的大紙（sheet）上。1979 年出現第一套電子試算表 VisiCalc，讓很多公司第一次買電腦；Excel 在 1985 年問世。


Data（資料）：拉丁文 datum「被給予的東西」，複數是 data。資料就是「別人交給你的事實」。



重點回顧
    

  1. 列是一筆紀錄，欄是一種資訊。
    2. 

  2. 一格一事、寫法統一、每筆有唯一編號。
    3. 

  3. 合計列、重複資料要排除，不然數字會變成兩倍。



小測驗：為什麼把「合計」列一起加總，結果會錯？




C。這是工廠報表最常見的錯誤之一，在清洗機裡你已經親眼看到了：4,185 會變成 8,370。

JavaScript：1995 年，布蘭登‧艾克只花了大約 10 天就做出雛形。原本叫 Mocha、又改成 LiveScript，後來為了搭當時很紅的 Java 語言的順風車才改名——其實它跟 Java 沒什麼關係，就像「鳳梨」和「梨子」一樣。

工廠數字的正確算法
理解 SMV 和效率，學會「加權」為什麼比「平均」正確，並把規則教給 Claude。



生活比喻

先認識 SMV 和效率


：一件衣服「標準上」要花幾分鐘做完。例如一件 T 恤 SMV 12 分鐘，代表熟練的人按標準方法做，大約 12 分鐘。


效率 ＝ 產出的標準分鐘 ÷ 投入的分鐘
＝（產量 × SMV）÷（人數 × 工時 × 60）


例：Line 1 有 50 人做 8 小時，投入 50×8×60 = 24,000 分鐘；做了 1,500 件、SMV 12，產出 18,000 標準分鐘。效率 = 18,000 ÷ 24,000 = 75%。

  • 用關鍵字找欄位：生產計畫表每個月欄位位置會移動，所以不寫死「第 5 欄是產量」，而是去找「標題有『產量』兩個字的那一欄」。
    • 

  • 排除合計列：款號和客戶都空白的列，就是合計列。
    • 

  • 一週從星期一開始。
    •

【VRT 計算規則】
1. 效率一律用加權：Σ(產量×SMV) ÷ Σ(人數×工時×60)，禁止把各線效率直接平均。
2. 線別一律寫成「Line N」（例：L3、3線、line 03 都改成 Line 3）。
3. 款號和客戶都空白的列視為合計列，不列入計算。
4. 欄位用標題關鍵字尋找，不用固定欄位位置。
5. 一週從星期一開始。
6. 算完請列出每條線的計算過程，方便我抽查。



名詞由來

IE（工業工程）：Industrial Engineering。美國工程師泰勒拿著碼表研究工人每個動作花幾秒，1911 年出版《科學管理原理》；吉爾布雷斯夫婦則拍影片研究「多餘的動作」。SMV 就是從這些「時間研究」發展來的。


WIP（在製品）：Work In Progress，已經開始做、還沒做完的貨。WIP 太多代表產線卡住了。


Lean（精實）：1988 年研究者克拉夫奇克研究豐田汽車的生產方式後，用 lean（瘦、沒有贅肉）來形容它：沒有浪費。



重點回顧
    

  1. 效率 = 產出標準分鐘 ÷ 投入分鐘。
    2. 

  2. 合計多條線要加權，不能直接平均。
    3. 

  3. 把規則寫成文件放進專案，Claude 就每次都算對。



小測驗：一條 10 人的小線效率 95%，一條 50 人的大線效率 65%。兩條線合計效率比較接近？




B。假設工時和 SMV 條件相同，大線人多、份量重，合計會被拉向 65%：(10×95 + 50×65) ÷ 60 ≈ 70%。
